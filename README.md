# เว็บแอป ITPC Techcare 🎓

เว็บแอปพลิเคชันสำหรับครูที่ปรึกษาและผู้ดูแล ใช้บันทึกและติดตามการดูแลนักเรียนรายเคส ออกแบบให้รองรับการใช้งานบนมือถือเป็นหลัก (Mobile-First) และใช้งานบนคอมพิวเตอร์ได้อย่างสมบูรณ์ ด้วยโทนสีประจำมหาวิทยาลัยเชียงใหม่ (CMU Purple `#784ba3` / `#9f77b4`) ผสมผสานสีพาสเทลเพื่อความสบายตาและอ่านง่าย

---

## 🌟 ฟีเจอร์หลัก

### 1. ปฏิทินเคส (Case Calendar)
- แสดงปฏิทินรายเดือน รายสัปดาห์ และมุมมองรายการ (List view)
- ไฮไลต์วันปัจจุบัน และตัวกรอง **เฉพาะเคสของฉัน** หรือดูเคส **ทั้งหมด**
- ป้ายประเภทเคส พร้อมจำนวนนักเรียน และสีระบุสถานะ (วางแผน `planned` / เสร็จสิ้น `done`)
- ปุ่มลอย (+) สำหรับเปิดเคสใหม่:
  - เลือกนักเรียนได้หลายคน (ค้นหาตามชื่อ/รหัส/ชื่อเล่น พร้อมตัวกรองชั้นและห้อง)
  - เลือกประเภทเคส: นักเรียนไม่มั่นใจในตัวเอง, นักเรียนรู้สึกว่าตัวเองเรียนไม่เก่ง, หรือ อื่นๆ (พร้อมระบุข้อความ)
  - รายละเอียดเพิ่มเติม, วันและเวลา
  - เลือกผู้ดูแลได้หลายคน (ผู้สร้างถูกเลือกเป็นผู้ดูแลโดยอัตโนมัติ)
  - เคสจะปรากฏบนปฏิทินของผู้ดูแลทุกคนที่เกี่ยวข้องทันที

### 2. รายละเอียดเคสและการดำเนินงาน (Case Detail & Updates)
- แสดงข้อมูลเคส นักเรียน และผู้ดูแลทั้งหมด
- ผู้ดูแลที่เกี่ยวข้องสามารถกดปุ่ม **อัปเดตเคส** เพื่อบันทึก:
  - สิ่งที่ทำ (Activity Note)
  - ผลที่ได้ (Result Note)
  - ขั้นตอนต่อไป (Next Step)
  - ปรับสถานะเป็น "เสร็จสิ้น"
- **แก้ไขและลบเคส**: ผู้ดูแลสามารถแก้ไขข้อมูลเคสหรือลบเคสได้ (มีกล่องยืนยัน)
- **ระบบเซ็นชื่อดิจิทัล (Digital Signature)**:
  - ช่องวาดลายเซ็นด้วยนิ้วหรือเมาส์บน Canvas แบบสัมผัส
  - ระบุชื่อผู้เซ็นและบทบาท (เช่น นักเรียน, ผู้ปกครอง, ผู้ดูแล)
  - ปุ่มล้างลายเซ็นและบันทึกลงฐานข้อมูล

### 3. ระบบข้อมูลนักเรียน (Students Management)
- แสดงรายชื่อนักเรียน ค้นหาตามชื่อ รหัสนักเรียน หรือชื่อเล่น
- ตัวกรองตามระดับชั้นและห้องเรียน
- แสดงจำนวนเคสที่นักเรียนแต่ละคนมีส่วนร่วม
- เพิ่ม / แก้ไข / ลบข้อมูลนักเรียนได้โดยตรง
- **หน้าประวัตินักเรียน (Student History)**: แสดงข้อมูลนักเรียนและไทม์ไลน์เคสทั้งหมดเรียงตามวันเวลา

### 4. การส่งออกรายงาน (Export Reports)
- **ส่งออก PDF รายเคส**: สรุปหัวข้อเคส นักเรียน ผู้ดูแล ประวัติการดำเนินงาน และภาพลายเซ็นดิจิทัล
- **ส่งออก PDF ประวัตินักเรียน**: สรุปภาพรวมและประวัติทุกเคสของนักเรียน
- **เทคโนโลยี PDF ภาษาไทยไม่เพี้ยน**: ใช้การเรนเดอร์เอกสาร A4 ความละเอียดสูงร่วมกับฟอนต์ Noto Sans Thai ทำให้วรรณยุกต์และสระภาษาไทยถูกต้อง 100%
- **ส่งออก Excel (.xlsx)**:
  - ส่งออกประวัติเคสรายนักเรียน
  - ส่งออกสรุปเคสประจำเดือนจากหน้าปฏิทิน

## 🛠️ สแต็กเทคโนโลยี (Tech Stack)

- **Frontend**: Next.js 16 (App Router) + TypeScript + Tailwind CSS
- **Database**: Supabase (PostgreSQL) ผ่าน Client Library `@supabase/supabase-js` โดยใช้ **anon key เท่านั้น**
- **Authentication**: PIN Authentication ผ่าน Supabase RPC (`verify_pin`) ไม่ใช้ Supabase Auth
- **Icons**: Lucide React
- **Exporting**: jsPDF, html2canvas, XLSX (SheetJS)
- **Date Handling**: date-fns (พร้อม locale ภาษาไทย)

## 🚀 การติดตั้งและเปิดใช้งาน (Getting Started)

### 1. ติดตั้ง Dependencies
```bash
npm install
```

### 2. ตั้งค่าตัวแปรแวดล้อม (Environment Variables)
คัดลอกไฟล์ `.env.example` ไปเป็น `.env.local` แล้วใส่ค่า URL และ Anon Key ของ Supabase:
```bash
cp .env.example .env.local
```
ภายในไฟล์ `.env.local`:
```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

### 3. รันโปรเจกต์ในโหมดพัฒนา (Development Mode)
```bash
npm run dev
```
เปิดเบราว์เซอร์ไปที่ `http://localhost:3000`

## 🗄️ ลำดับการรันไฟล์ SQL ใน Supabase SQL Editor

ให้เปิดหน้า **SQL Editor** ใน Supabase Dashboard แล้วรันไฟล์ตามลำดับดังนี้:

1. **`sql/01_schema.sql`**
   - เปิด extension `pgcrypto` สำหรับการเข้ารหัส hash PIN
   - สร้างตาราง `students`, `caretakers`, `cases`, `case_students`, `case_caretakers`, `case_updates`, `case_signatures`
   - กำหนด Primary Key, Foreign Key (พร้อม `ON DELETE CASCADE`), Indexes และ Trigger อัปเดต `updated_at` อัตโนมัติ
   - *ปลอดภัยในการรันซ้ำด้วย `IF NOT EXISTS` และ `CREATE OR REPLACE`*

2. **`sql/02_rls_policies.sql`**
   - เปิดใช้งาน Row Level Security (RLS) บนทุกตาราง
   - กำหนด Policy ให้ role `anon` สามารถ อ่าน/เพิ่ม/แก้ไข/ลบ ได้ตามขอบเขตที่ระบบต้องการ
   - *ปลอดภัยในการรันซ้ำด้วย `DROP POLICY IF EXISTS` ก่อนสร้าง*

3. **`sql/03_functions.sql`**
   - ฟังก์ชัน RPC `verify_pin(p_caretaker_id, p_pin)`: ตรวจสอบ PIN ผ่าน `crypt()` บนฐานข้อมูลโดยไม่ส่ง PIN hash กลับมาที่ client
   - ฟังก์ชัน `get_caretakers()`: ดึงรายชื่อผู้ดูแล (เฉพาะ id และ name) ปลอดภัยไม่ส่ง pin_hash
   - ฟังก์ชัน `create_case_with_relations(...)`: สร้างเคสพร้อมเชื่อมโยงนักเรียนและผู้ดูแลทั้งหมดใน 1 Transaction

4. **`sql/04_seed.sql`**
   - ข้อมูลตัวอย่างนักเรียน 10 คน
   - ข้อมูลผู้ดูแลตัวอย่าง 3 คน
   - เคสตัวอย่าง 5 เคส พร้อมประวัติการดำเนินงานและลายเซ็น

5. **`sql/05_crud_examples.sql`**
   - ไฟล์รวมตัวอย่างคำสั่ง CRUD (INSERT, UPDATE, DELETE) สำหรับทุกตาราง พร้อมคอมเมนต์อธิบายภาษาไทย สำหรับใช้ทดสอบรันใน Supabase SQL Editor

## 🔒 ข้อจำกัดด้านความปลอดภัยของการใช้ Anon Key อย่างเดียว (Security Considerations)

ระบบนี้พัฒนาตามข้อกำหนดโดยใช้ **Supabase Anon Key เท่านั้น** (ไม่มี Supabase Auth และไม่มี Service Role Key) จึงมีข้อจำกัดและข้อควรระวังด้านความปลอดภัยที่ต้องทราบดังนี้:

1. **การตรวจสอบสิทธิ์บนฝั่ง Client**:
   - การตรวจสอบผู้ดูแลทำผ่านการเลือกชื่อและกรอก PIN โดยส่งไปตรวจสอบผ่าน SQL Function `verify_pin` (RPC) ที่ใช้ `crypt()` ของ `pgcrypto`
   - เมื่อผ่านการตรวจสอบ ข้อมูลผู้ดูแล (`id`, `name`) จะถูกบันทึกใน `localStorage` ของเบราว์เซอร์
   - ข้อจำกัด: ผู้ใช้งานที่มีความรู้ด้านเทคนิคสามารถแก้ไขค่าใน `localStorage` ได้ จึงเหมาะสำหรับระบบงานภายในที่ครูใช้งานร่วมกัน

2. **Row Level Security (RLS) ร่วมกับ Anon Role**:
   - เนื่องจากคำขอทั้งหมดส่งผ่าน Anon Key นโยบาย RLS จึงถูกเปิดให้ role `anon` ใช้งาน
   - ฐานข้อมูลใช้การจำกัดสิทธิ์ในระดับฟังก์ชัน (Security Definer) เพื่อไม่ส่งข้อมูล `pin_hash` ออกมายัง Client และใช้ Check Constraint ในระดับตารางเพื่อความถูกต้องของข้อมูล (เช่น การบังคับกรอก `other_text` เมื่อเลือกประเภทเคสเป็น `other`)

3. **คำแนะนำสำหรับการนำไปใช้งานจริง (Production)**:
   - หากต้องการระดับความปลอดภัยสูงสุดในอนาคต ควรพิจารณาใช้งาน Supabase Auth ควบคู่กับ JWT Claims เพื่อให้ RLS สามารถตรวจสอบ `auth.uid()` ของผู้ใช้แต่ละคนได้อย่างเข้มงวดยิ่งขึ้น
